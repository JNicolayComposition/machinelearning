Three Demo Systems

How do different technologies invite different bodies, gestures and musical behaviors?

System A — Sensor → OSC/BLE → TouchDesigner

ESP32 + ICM sensor with OSC or alternatively a Seeed sensor via BLE. OSC is often faster and more stable for performances; BLE is easier and wireless but can be more fragile regarding latency, pairing and connection stability.

System B — Web App Client/Master/Server

A browser-based motion visualization system using smartphone sensors. Use the master page on a laptop or projector and the client page on an iPhone in Safari. Enable sensor permissions.

System C — Wekinator + Python Camera App + SuperCollider

A mini beat machine: the camera app sends visual features to Wekinator, Wekinator classifies gestures or states, and SuperCollider turns the output into sound.

Key Takeaways for the Whole Course

Technology shapes embodiment

Interactive systems change how performers move, listen and adapt.

Mapping is composition

The translation from body to data to output is an artistic decision.

ML is performative

Training, retraining and misclassification become part of rehearsal and performance.

Materials become practice

Code, short videos, worksheets and sketches support embodied experimentation.

TouchDesigner / Data Streams / Smoothing

In TouchDesigner, sensor data arrives as continuous streams. Values may jitter, drift or spike. Smoothing reduces jitter but adds delay. Thresholds turn continuous data into triggers. Musically: raw data can feel percussive, smoothed data can feel lyrical, delayed data can feel heavy or resistant.

Continuous, Discrete and Smoothed Mapping

A continuous mapping turns a changing value into another changing value. A discrete mapping turns a value into an event. Smoothing makes motion more fluid; thresholds make triggers clearer.
